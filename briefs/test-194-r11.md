and the reference arm pinned to **the unexported helper the seam itself uses** so it

**That last one is the interesting one.** A reference arm that calls the same helper as

test would still catch if the shared helper were itself wrong.**

Its positive control is `TestLabelWritePrice_MonotonicityPinCanFail`. **Run it. Do not
read it.** Confirm (a) it fails, (b) it fails *for the monotonicity reason* and not
because it does not compile or panics, and (c) the failure it induces is one the real pin
would actually see — a positive control that trips a different arm than the one it
guards is the recurring defect on this project.

**Then do the harder thing: a count-neutral corruption.** The bar on this project is that
a count-pin RED is not evidence of non-vacuity unless a **count-neutral** corruption is

**And say where you stopped.** The count-neutral bar now reaches the fixture corpus and
