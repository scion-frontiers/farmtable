# The ruling you are implementing

Two rulings landed this session. Both supersede anything you may find in earlier round briefs.

**RULING 1 — the general principle, not the `enabled` case.**

> The scope required to WRITE a label must be computed from the set of labels that could **ever**
> be lifecycle-authoritative under **any configuration this deployment might adopt** — not from the
> set that is authoritative under today's configuration.

The earlier ruling said only "the write side must never depend on `enabled`". That was too narrow.
`audit-194-r9` measured three independent axes that each produce the identical defect, and only one
of them involves the toggle `[MEASURED — audit-194-r9]`:

```
axis 1  enabled false -> true                 ft:stage/completed   priced-at-write FALSE, later authoritative
axis 2  push_prefix "ft:" -> "ft2:"           ft2:stage/completed  priced-at-write FALSE, later authoritative
axis 3  stages gains {shipped: completed}     ft:shipped           priced-at-write FALSE, later authoritative
```

Axes 2 and 3 need no toggle at all. `LabelConfig` has five fields — `Enabled`, `Stages`,
`Priorities`, `Types`, `PushPrefix` (`config.go:24`) — of which three are measured above and two are
not. **A fix that closes the measured axes and is silent about the rest is a checklist over an open
set.** Close the class.

**RULING 2 — "the write side" includes the predicate.**

"The write side" must be read to include the predicate that decides **which labels are lifecycle
labels**, not merely the scope lookup that follows. If the write path still asks "is this a
lifecycle label?" against today's config, an axis-2 or axis-3 label is never recognised as a
candidate and the any-configuration principle never gets a chance to run.

# Verification — non-negotiable, and read this before you design a single test

The control you are fixing is inert in production for **two independent reasons**, so a naive
end-to-end check after your fix lands is uninterpretable in *both* directions — green proves
nothing and red proves nothing.

- **Arm 1** — the toggle. That is the bug you are fixing.
- **Arm 2** — the credential. `RequireScope` treats an **empty** scope set as a wildcard
  (`scopes.go:83-85`). The coordinator checked production `api_tokens` directly: the token carrying
  essentially all real traffic is empty-scoped (wildcard), and the only narrow-scoped token that
  exists has **never been used** `[MEASURED — coordinator, production]`. So a bare `task:write`
  holder — the population this control protects — may currently be of size zero in practice.

Fixing arm 1 while arm 2 stands changes nothing observable. **Therefore your verification must be a
four-cell matrix, and you must state which single cell can falsify your fix:**

|  | wildcard / empty-scoped principal | narrow-scoped principal (explicit `task:write`, no close/transition scope) |
|---|---|---|
| **mapping enabled** | positive control — must be ALLOWED | must be REFUSED |
| **mapping disabled** | positive control — must be ALLOWED | **must be REFUSED — this is the cell that proves the fix** |

The bottom-right cell is the only one that can fail if your fix is wrong. The wildcard column is the
positive control proving a refusal is caused by the **scope** and not by some unrelated breakage —
without it, "refused" and "broken" are the same observation. Construct the narrow-scoped principal
in-process; do not depend on a production token.

Extend the same matrix over the config axes from Ruling 1 — at minimum `PushPrefix` and a `Stages`
alias, since those are measured — and say what you did about `Priorities` and `Types`.

# Method

- **A negative claim needs a positive control. Every one.** "I grepped and found nothing" is not a
  result unless you also show the grep finding something it should find.
- **Read messages, not exit codes and not counts.** Two arms returning the same value for different
  reasons is the recurring way this project has fooled itself, and I did it again this session.
- **Never read an exit code through a pipe.** `cmd > f 2>&1; echo $?`, not `cmd | tail`.
- **Revert probes by snapshot restore (`cp` from `/tmp`), never `git checkout`** — a previous leg
  lost uncommitted work that way. Assert `git status --porcelain` is empty after each cell and
  report the count of cells left dirty.
- **Predict before you measure and report your misses.** The sharpest finding in each of the last
  three rounds came from someone chasing a prediction that turned out wrong.
- **Separate observation from inference, in those words.** A correct fact carrying a wrong inference
  is more dangerous than a wrong fact, because the fact survives verification and the inference
  rides in behind it. I did exactly this to a leg this session; do not inherit it.
