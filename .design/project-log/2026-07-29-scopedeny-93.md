## What was measured

All at `faf1c8c` unless stated. Anything attributed to main was re-derived
locally rather than taken from a briefing.

- **Two coupled reads in `internal/server/scopes.go` produce privilege
  escalation.** `DefaultScopesForUserType`'s default arm returns `nil` for an
  unrecognised type after logging a warning; `RequireScope` reads `nil`/empty as
  wildcard. Together a `--type` typo yields full admin. Measured: types
  `"reviewr"`, `"superuser"`, `"Admin"` and `""` each reached
  `collection:admin` GRANTED.
- **The halves are asymmetric.** Changing the `RequireScope` read alone already
  stops the escalation. The default arm's distinct contribution is turning a
  silently dead token into a loud refusal to mint one. Either alone is
  insufficient for a different reason each.
- **A rejection change is a no-op for new SSO logins.**
  `internal/serverapp/provisioning.go:92` hardcodes `Type: "human"` for every
  OAuth/IAP user, and `"human"` resolves to wildcard — as do `"admin"` and
  `"service_account"`. The lockout exposure on that path is confined to
  **existing** users, whose stored type is returned unchanged by
  `FindOrCreateByEmail` and passed straight to `CreateSessionToken`.
- **The restricted tier is close to unreachable.** `"admin"`, `"reviewer"`,
  `"orchestrator"` and `"viewer"` each appear in exactly one non-test,
  non-generated Go file — `internal/server/scopes.go`, their own switch arm.
  Nothing writes them.
- **Session tokens are not part of the empty-scope population.**
  `CreateSessionToken` passes `DefaultScopesForUserType` through, so a `"human"`
  session token carries an explicit `["*"]`, not an empty set.
- **19 of 19 API tokens in the measured database hold NULL scopes.** Snapshot of
  `/workspace/.farmtable/farmtable.db` (mtime 2026-07-28 12:30), queried
  read-only via a throwaway Go program — no `sqlite3` binary in this
  environment. `dashboard-f69` (1 of the 19) is generated by no code path in
  this repository; it was created out-of-band, and is the concrete instance of
  the class a name-scoped repair cannot reach.
- **Zero non-vocabulary user types, over n=1 user.** Reported as the very small
  sample it is; it establishes nothing about deployments.
- **Import is an unmeasurable producer of such rows.** `ImportCollection` writes
  `imported.Type` verbatim with no validation, and
  `internal/store/schema/user.go:19` has no enum constraint. It creates no
  tokens, so imported users land in the "cannot mint" class rather than the
  "suddenly blocked" class — except where they also authenticate via SSO.
- **Main already acknowledges the scope-less population.** `ft token update`
  ships an `UNSCOPED_TOKEN` guard rail describing "a token with no stored scopes
  (legacy wildcard)".

## Open sites not in the original candidate set

- `server.userTypeToProto` (`convert.go:202`) coerces unrecognised types to
  `AGENT` — and also the valid `reviewer`, `orchestrator` and `viewer`, which
  have no proto enum member. This makes the model unobservable: `ft user get`
  cannot report the field an operator would need to diagnose a type problem.
- `ft token list` omitted empty scope sets, rendering a scope-less token
  identically to a healthy one.
- `ft token update` help documented the permissive rule.
- `ImportCollection` ingestion — owned by `dev-import-hardening`. Flagged
  upward: I was given one `SetType` site, another leg found three.

## Notes for whoever picks this up

- `RequireCollectionAccess` must **not** be made symmetric with scope handling.
  Collection IDs are a restriction list where empty means unrestricted; scopes
  are a grant list where empty means nothing. Making them symmetric would lock
  every user out of every collection.
- Commit `22dbfaf` pins what every named arm returns today and asserts nothing
  about what any should return, so whichever way the SSO-privilege question is
  answered, the change produces a visible RED naming the arm that moved. Verified
  non-vacuous. Worth keeping independently of everything else here.
- The branch's middle commits do not build: `rbac_test.go` kept a one-value call
  signature after `c8be951` moved it to two values, with the repair sitting
  uncommitted. Every green run reported during the task therefore measured the
  working tree, not a commit. `1cbf643` records it; only the tip is
  independently reproducible.
- `internal/cli` requires the `//go:embed all:web/dist` tree to build;
  `internal/server` and `internal/serverapp` do not. Fresh worktrees need
  `web/dist` copied in from the canonical clone.
