## Findings by severity

### H-1 (High) — the write predicate captures `<namespace>:<stage-name>`, and the test that exists to bound it is blind

`stripAnyLifecyclePrefix` (`lifecycle_claim.go:166`) strips *any* leading `<x>:`
segment, then asks whether the remainder names a stage. Because the ten stage names
are bare words (`triage`, `working`, `completed`, `duplicate`, `cancelled`, …), **any
label of the form `<anything>:<stage-name>` is now claimed as a lifecycle stage
assertion.** So is bare `stage/<stage-name>`.

Measured end to end through `FarmTableService.UpdateTask`, narrow principal
(`task:read`,`task:write`), **default config, toggle ON**:

| label added | pre-fix (`06f01d7`) | post-fix (`6d8f19e`) |
|---|---|---|
| `status:duplicate` | allowed | **DENIED** |
| `kanban:working` | allowed | **DENIED** |
| `release:completed` | allowed | **DENIED** |
| `epic:cancelled` | allowed | **DENIED** |
| `stage/completed` | allowed | **DENIED** |
| `area:triage`, `team:in_review`, `scope:deploying` | allowed | allowed |
| `priority:high`, `bug`, `needs-triage`, `status:blocked` | allowed | allowed |

Reproduce:

```bash
# probe file contents in "Reproduction" section below
go test ./internal/server/ -run TestZZProbeWidening -count=1 -v
```

`status:`, `release:`, `epic:` and `kanban:` are ordinary GitHub label-namespace
conventions. A `task:write` agent doing routine triage on a repo using them is now
refused with `PermissionDenied: task:close`.

**Why this is a test finding and not only a code finding.**
`TestLabelWriteScope_PriorityAndTypeAxesDoNotPriceStages` exists for exactly this — its
own failure message reads *"DENIAL OF LEGITIMATE WORK … The round-10 claim predicate
has widened too far."* Its three free rows are `priority:high`, `bug`, `needs-triage`.
**None of them is namespaced with a stage-name suffix**, so the row that would fire is
absent. The test cannot fail for the reason it was written.

The project log rates this class of bug "as seriously as an underpriced write" (D3,
axis 3) and the code comment says the same. The round then shipped an instance of it.

Minimum fix on my axis: add rows for `status:duplicate`, `release:completed` and
`stage/completed` to that table and let it be red until the predicate is narrowed
(e.g. requiring the local prefix *or* a `stage/` segment, rather than any `:`).

### M-1 (Medium) — the `absent` table fails the count-neutral bar: 3 of 3 payloads replaced with junk, count held, GREEN

`TestUpdateTask_CrossListCancelCannotApplyATerminalLabelForFree` is described in its
own new guard message as *"the pin for THE CRITICAL"*. Count-neutral corruption:

```
absent[0]: add/remove {completed}                 -> {"junk-x"}/{"junk-x"}
absent[1]: add/remove {UPPER(completed)}/{completed} -> {"JUNK-Y"}/{"junk-y"}
absent[2]: add/remove {completed}/{"  "+completed+"\t"} -> {"junk-z"}/{"  junk-z\t"}
```
count held at 3 → **`ok`  (GREEN)**

Root cause: the subtest assertions reference the **fixed literal `completed`**, never
`row.add`/`row.remove`. The row data selects the attack payload; the oracle checks a
constant. With a junk payload nothing lands, so "completed did not land" is trivially
true. Nothing in the test observes row identity — the new `executed` counter observes
only row *count*.

This is the exact bar the shared block adopted after the 8-of-14 measurement. Contrast
`TestUpdateTask_APricedRemovalLandsWhateverTheCallerSpelling`, whose 3 callers I
corrupted count-neutrally and which went **RED** correctly — because its assertions do
consume `sp.caller`.

## Deliverable 4 — the 8th shape

**The brief is wrong that the leg did not explain it.** Project log line 39: *"the same
harness discriminates 7 of the 8 shapes (`PRICED=true`), and correctly reports the
eighth — **adding an unrelated label** — as free."*

**Its non-discrimination is benign, and I verified why.** An unrelated label produces
no stage change, so `before == after` and `PRICED=false` is the *correct* answer, not a
blind spot. It is also the row that makes the harness a two-sided control: without a
cell that legitimately reads false, a harness that returned `PRICED=false`
unconditionally would be indistinguishable from a working one on the other seven.

The residual caution: the leg's positive control therefore has discriminating power on
7 cells, not 8, and a dead harness would match on that eighth cell. That is a strength
of the design, not a hiding place — the seven others exclude the dead-harness
hypothesis. **Answer: identified, explained by the leg, benign.**
