Bottleneck: Task A — blocks 2 tasks directly

Analysis: GetBottlenecks returns no items because the seeding loop only checks
SourceRelationships for "blocks" edges. When dependencies are created via
--blocked-by, Task A has no SourceRelationships with type "blocks" — instead,
Tasks B and C have TargetRelationships pointing back to Task A. The seeding
loop misses Task A entirely, so no candidates are found.
