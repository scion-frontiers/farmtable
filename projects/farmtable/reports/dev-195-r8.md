## The thing nobody found: C7-l, a live arity bypass

Not in the brief. Found by doing the cheapest non-blocking item on the list.

`renderMarkdownArityViolation` captured its parameter list with
`/export function renderMarkdown\s*\(([^)]*)\)/g`. `[^)]*` stops at the first
`)`, and **a parameter type is allowed to contain one.** Against the real
`markdown.ts`:

```ts
export function renderMarkdown(
  md: string | ((x: string) => string),
  opts: { inline?: boolean } = {},
): string
```

captured as `md: string | ((x: string` → one parameter, no default, no rest →
`null`.

**GREEN at 78 checks / 122 assertions with `tsc --noEmit` clean**, against an
implementation taking a real, usable second parameter — the configuration
channel into the sanitizer that the pin exists to deny. `Function.length` was
blind too, the second parameter being defaulted, so **both halves of the arity
pin missed the same declaration.** This is the third instance in this one pin of
the defect its own docblock names: a check that stops at the first thing it finds
cannot see the second.

Fixed with `balancedDeclarationParameterLists` (depth counting, as
`callArguments` already did) and pinned as C7-l and C7-m.

Why it went unnoticed for three rounds: the two false-positive spellings the
brief cites (`md: (x: string) => string`) were **unreachable** through the
truncating regex, so the `hasTopLevelDefault` bug and the truncation bug masked
each other. Adding the fixture with only the rename applied left the suite green
— my first control **failed to go red**, which is what exposed the truncation.
