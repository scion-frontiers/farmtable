## THE OPEN FINDING

**The ruling handed me a question with "MEASURE IT. If it is closed, say so… If it is open,
STOP and tell me; it is a new finding and not yours to fix silently in this round."**

**It is OPEN. I have not fixed it.**

The gate at `server.go:840-860`, priced via `store.LabelDeltaLifecycleStages`, prices **nothing**
when `github.labels.enabled=false`. Caller-supplied `add_labels` therefore goes through
unpriced, and the label it writes is durable.

Measured differential, same request under both toggle settings:

```
enabled=true   add ft:stage/completed with task:write
               -> PermissionDenied, requires task:close
               -> labels stay [bug]

enabled=false  add ft:stage/completed with task:write
               -> nil (accepted)
               -> labels now [bug ft:stage/completed]
               -> AFTER FLIP-ON: stages = [completed], available = false
```

**Why it matters, in the ruling's own terms.** A holder of bare `task:write` durably writes a
lifecycle label while the toggle is off. The label persists in GitHub, which does not know about
the toggle. Whenever an operator later flips `enabled: true` — a config change nobody would
regard as a privilege grant — that label becomes **authoritative and terminal**, moving the task
to `completed` and making it unavailable, with **no transition scope ever charged**. Reversing it
