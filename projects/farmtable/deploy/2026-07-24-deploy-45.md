Key changes in this deploy (Performance Phase 1, PR #149):
1. **getChildren() O(n^2) → O(1)**: Replaced per-call `array.filter()` with a
   cached `Map<parentId, Task[]>` maintained incrementally on `upsert()`/`delete()`.
   At 10k nodes this reduces render-path child-lookup cost from ~800ms to <1ms
   (2,120x speedup in synthetic benchmarks).
2. **Default depth limit for large collections**: Auto-sets `maxDepth=3` when
   a collection exceeds 500 tasks, reducing rendered nodes from ~10k to ~1k
   (88-98% reduction). A "N deeper levels hidden" badge appears in the hierarchy nav.
   The user can override via the Level dropdown at any time; small collections
   are unaffected.
3. **Defensive copies**: `getChildren()`/`allTasks`/`roots` return shallow copies
   with readonly return types. `byParent` getter typed as `ReadonlyMap`.
4. **Lifecycle correctness**: `super.willUpdate(changedProps)` called in ft-tree-view.

Files changed: `task-store.ts`, `ft-tree-view.ts`, `ft-hierarchy-nav.ts`,
`ft-dashboard-view.ts`, `ft-inspector-relationships.ts`.

**PERFORMANCE-FOCUSED DEPLOY** — core optimization for large-collection
rendering. No new features, no changes to data model or API.

### Comparison to Baseline

| Phase | Pre-Fix (investigation est.) | Post-Fix (live measured) |
|-------|------------------------------|--------------------------|
| Total time to interactive | 17,000-25,000ms | **2,999ms** |
| Nodes rendered | ~10,000 | 1,036 |
| Node reduction | - | 88.8% fewer nodes |

**Real-world improvement: 6x-8x faster** (from 17-25s estimated → 3.0s measured).

Note: The pre-fix baseline of 17-25s was estimated from synthetic benchmarks in
the investigation report (code analysis + dagre benchmarks + DOM estimates) since
no live profiling of a 10k-task collection was possible at the time (IAP auth
prevented browser DevTools profiling). The 3.0s post-fix measurement is the
first actual live end-to-end measurement from navigation to interactive.

The improvement is somewhat lower than the synthetic estimate of ~166x because:
1. The live measurement includes network transfer time (~2-3s for 9,284 tasks via
   gRPC streaming), which is a fixed cost unaffected by the rendering fix.
2. The depth limit reduces to 1,036 nodes (not 156 as in the synthetic model,
   because this real tree has a higher branching factor than the idealized
   branching-factor-5 model).
3. Despite only being 6-8x faster overall, the *rendering* portion specifically
   dropped from ~17-22s to well under 1s — the remaining 3s is dominated by
   data transfer, which is a separate bottleneck (addressed in the investigation
   report as Phase 2+).
