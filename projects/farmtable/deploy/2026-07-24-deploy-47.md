Key changes in this deploy (PR #151, periodic redraw fix):
1. **Root Cause 1 — `ClosedAt = time.Now()`**: For closed GitHub issues polled
   via the passthrough path, `ClosedAt` was set to the current server time on
   every `ListTasks` call instead of using GitHub's actual `closedAt` timestamp.
   This produced a different value every poll cycle, defeating the
   `TaskStore.upsert()` equality check (Feature 55) and triggering a UI re-render.
   **Fix**: Use the real `issue.ClosedAt.Time` from the GraphQL response, with a
   defensive fallback to `UpdatedAt.Time` if `ClosedAt` is somehow null.
2. **Root Cause 2 — non-deterministic `remoteData` key ordering**: The
   `TaskStore.upsert()` equality check used `JSON.stringify()`, which is
   sensitive to object key insertion order. GitHub tasks carry `remoteData`
   populated from Go `map[string]any` via `structpb.NewStruct()`, which has
   non-deterministic iteration order. Different key orderings between polls
   produced different `JSON.stringify()` outputs even when data was unchanged.
   **Fix**: Replaced `JSON.stringify` with `stableStringify()` that sorts object
   keys recursively before stringifying.

Files changed: `internal/platform/github/passthrough.go`,
`internal/platform/github/graphql_queries.go`, `web/src/store/task-store.ts`.

**MODERATE-RISK DEPLOY** — touches the universal `TaskStore.upsert()` equality
check used by ALL tasks (native + external) and the GitHub passthrough polling
path. Verified carefully that native collections are unaffected.
