Key changes in this deploy:
- **Feature 60: Dependency View Viewport Stability** (PR #137):
  Fixes the Dependency view's viewport (pan+zoom) resetting on every poll/stream
  tick for external/polling collections. Two fixes:
  1. **structureKey() sort**: Relationships are now sorted before hashing in the
     structure comparison key, so re-ordered (but unchanged) data from the API
     no longer triggers a full re-layout and viewport reset.
  2. **snapshotComplete guard**: PollManager's `refresh()` now only fires
     `snapshotComplete` when data actually changed (TaskStore's `upsert()` returns
     a boolean), preventing spurious `requestUpdate()` on all views.

## Feature 60 Live Validation — Viewport Stability (CRITICAL)

### Method

A Playwright (Chromium) automation script (`verify-f60-viewport.mjs`) connects
to the LIVE deployed site at `https://farmtable-486315127503.us-central1.run.app`
via IAP (Authorization: Bearer <IAP-identity-token>) with the farmtable app
token passed via URL parameter. The script:

1. Opens each collection's Dependency view
2. Captures viewport state (panX, panY, scale) via `page.evaluate()` on the
   `ft-dependency-view` Lit element (Playwright locators pierce shadow DOM)
3. Interacts with the viewport (mouse wheel zoom + drag pan) to establish a
   non-default reference position
4. Samples the viewport state every 5 seconds for 40 seconds
5. Measures drift from the reference position
6. Also checks the Tree view for stability

### Important: Streaming vs Polling

All collections (including the external GitHub collection) now use **WatchTasks
streaming** (`connectionStatus: "live"`, `isPolling: false`) rather than
PollManager-based polling. The server implements WatchTasks for all collection
types. Feature 60's `structureKey()` sort fix applies equally to both streaming
and polling paths — it prevents viewport resets whenever the view's structure
comparison runs, regardless of how the data arrived.
