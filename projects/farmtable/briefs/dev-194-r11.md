## The ruling

Restated twice already. This is the current text and it supersedes both earlier ones.

> **Price a label as lifecycle-authoritative when it carries a recognised
> category-segment marker — the `stage/`-shaped segment that the internal convention
> actually uses to construct a lifecycle-stage label — and the suffix after that marker
> names a value authoritative under today's `Stages` configuration.**
>
> **Marker recognition must be delimiter-agnostic: recognise the category segment
> following either a colon or a slash.**
>
> **The prefix value remains irrelevant.** `ft:stage/completed`,
> `ft2:stage/completed`, `anything:stage/completed`, `ft/stage/completed` and
> `ft-stage/completed` price identically.
>
> **`Priorities` and `Types` are OUT.** Stages only.

Two changes from the version round 10 implemented against, and both matter:

1. **A bare `<x>:` prefix is no longer sufficient.** Round 10 stripped any leading
   `<x>:` and matched the remainder against bare stage names, which are common English
   words. That produced a **live regression denying ordinary work** — measured below.
   A recognised marker must now be present.
2. **Delimiter-agnostic.** Round 10 recognised only colon. Slash-style namespacing
   (`area/foo`, `kind/bug`, `status/blocked`) is the dominant GitHub convention, so the
   colon-only rule fixed the *less* likely foreign spelling and left the more likely one
   open.

`Priorities`/`Types` were dropped because two legs independently measured that they feed
no authorization or lifecycle decision and are already writable with `task:write` via
`UpdateTask(priority=…)`. The round-10 exclusion was correct; the ruling was too wide.

### B5 — Data race on shared mutable state (review R-1, audit F-3)

`labels.go:110-114`, `lifecycle_claim.go:172-182`. `writeViewMapper` writes
`m.writeView` under no lock. `LabelMapper` was immutable before this diff — this is its
first mutable field, which is why there is no mutex to reach for. The mapper is **not

collection and hands the same pointer to every request; each gRPC handler is its own
goroutine. `passthrough.go:31-42` already documents this, which is why `cacheMu` exists —
added for this exact class in #198. The diff adds shared mutable state next to that lock
and does not take it.

mapper's config field** racing `NewLabelMapper`'s construction. No happens-before edge,
so an observer may see `enabled=false`, an empty `labelToStage`, or an empty
`PushPrefix` — **every one of which biases toward refusing to recognise a label, i.e.
toward pricing a lifecycle write as free.** And `LabelDeltaLifecycleStages` calls
`lifecycleStagesForLabels` twice, each calling `writeViewMapper` twice, so the two
endpoints of one price can be computed under different views.

independently over a mutex. It removes the concept rather than guarding it, makes the
