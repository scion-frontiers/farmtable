Comparing sanitizer OUTPUT across the mutated configs.
A mutation is a GUARD GAP only if its output differs from baseline in a
security-relevant way. Identical output => the mutation is a no-op and
the suite staying green is CORRECT.

--- PRODUCTION (baseline) ---
  same      style attribute        "<p>x</p>"
  same      javascript: href       "<p><a>x</a></p>\n"
  same      md javascript: link    "<p><a>x</a></p>\n"
  same      unknown proto href     "<p><a>x</a></p>\n"
  same      data:text/html href    "<p><a>x</a></p>\n"
  same      vbscript: href         "<p><a>x</a></p>\n"

--- ADD_ATTR:[style] ---
  same      style attribute        "<p>x</p>"
  same      javascript: href       "<p><a>x</a></p>\n"
  same      md javascript: link    "<p><a>x</a></p>\n"
  same      unknown proto href     "<p><a>x</a></p>\n"
  same      data:text/html href    "<p><a>x</a></p>\n"
  same      vbscript: href         "<p><a>x</a></p>\n"

--- ALLOW_UNKNOWN_PROTOCOLS:true ---
  same      style attribute        "<p>x</p>"
  same      javascript: href       "<p><a>x</a></p>\n"
  same      md javascript: link    "<p><a>x</a></p>\n"
  DIFFERS!  unknown proto href     "<p><a href=\"evilproto:payload\">x</a></p>\n"
  same      data:text/html href    "<p><a>x</a></p>\n"
  same      vbscript: href         "<p><a>x</a></p>\n"

=== VERDICT PER MUTATION ===
  ADD_ATTR:[style]: SECURITY NO-OP (output identical on all 6 probes).
     -> suite staying green is CORRECT. NOT a guard gap.
  ALLOW_UNKNOWN_PROTOCOLS:true: WEAKENS the sanitizer on 1 probe(s): unknown proto href
     -> suite staying green IS a guard gap.
