Key changes in this deploy (Feature 66, PR #150):
1. **Sticky Solo state**: Solo (isolate) mode now persists when switching between
   Tree View and Dependency View. Previously, each view maintained its own
   isolateMode — now `ft-app` holds a single shared `isolateMode` property that
   is passed down to both views.
2. **`&solo=1` URL parameter**: Solo mode state is reflected in the URL for
   deep-linking. When Solo is active, `&solo=1` is appended; when cleared, it is
   removed. On page load, if `solo=1` is present with a valid `task=` parameter,
   Solo mode is restored.
3. **Bug fix — directed reachability BFS**: The previous BFS for Solo mode in
   Dependency View used a single shared visited set for both upstream (BLOCKED_BY)
   and downstream (BLOCKS) traversals. This caused the downstream BFS to skip the
   start node (already in the shared `ids` set), missing the entire downstream
   chain and showing extraneous sibling nodes via the undirected connected-component
   approach. Fixed by using per-direction `visited` sets in the `getDirectedReachableIds()`
   function.

Files changed: `ft-app.ts`, `ft-dependency-view.ts`, `ft-hierarchy-nav.ts`.
